<objective>
Step (3) of the roadmap's strict internal order: teach the Sanity schema to model Farsi posts as sibling documents linked to their English source, and close the write-path half of decision D-04.

This plan adds three fields to `src/sanity/schemaTypes/postType.ts`, extends the shared preview so language pairs are recognisable in the Studio (D-06), stamps `language: "en"` in both post-creating API routes (D-04), and extends the check script with mechanical schema-shape assertions.

Purpose: satisfy CONTENT-01's data-model half. Without these fields the migration in plan 02-04 has nothing to write into and the Studio split in plan 02-05 has nothing to filter on.
Output: three new schema fields, an extended preview, two one-line write-path stamps, and a schema section in the check script.

**Why the API stamp is the primary control and `initialValue` is the backup.** `initialValue: "en"` is a Studio form affordance. It runs when an editor opens a create form; it does not run for `client.create`, which is how both API writers create posts. A post submitted through the author dashboard or through `/api/v1/posts` would therefore land with no language field at all. The tolerant filter from D-03 means such a post still renders correctly on English surfaces, so this is survivable, but it would undermine "Farsi is always explicit" as a data invariant. D-04 exists precisely for this, and the API routes are the primary tier.

**Note on D-02 versus D-04 for `src/app/api/dashboard/author/submit-post/route.ts`.** D-02 forbids adding a language FILTER to anything under `src/app/api/dashboard/`. D-04 requires adding a language STAMP to the post writers, and one of them lives under that path. These do not conflict: this plan adds a field to a document being created, and adds no read filter anywhere under `api/dashboard/`. Both decisions are honoured.

**Phase 3 invariant recorded here (research Pitfall 8).** `src/app/api/cron/publish-scheduled/route.ts` finds scheduled posts whose publish time has passed, patches them to approved, and mails the entire subscriber list with an English subject line. It is deliberately unfiltered by D-02 and is not modified by this phase. The consequence is an invariant Phase 3 must inherit: **Farsi documents must never carry `status: "scheduled"`.** The design already lands them as drafts. This plan's SUMMARY must state it so the Phase 3 planner inherits it explicitly.
</objective>
