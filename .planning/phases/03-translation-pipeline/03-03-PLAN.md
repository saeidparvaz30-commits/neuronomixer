<objective>
Build the load-bearing correctness core of the pipeline as pure, offline-provable functions: the Portable Text walker that enumerates exactly which strings may be translated, the structural fingerprint that blocks a write when anything else moved, and the `translationNotes` formatter.

Purpose: naive whole-document translation is what destroys links, keys and block structure. D-05 tier 1 puts that judgement in code, never in the model. Everything here is provable with no network and no model, so the expensive parts of the phase are built on something already proven.
Output: two pure modules under a new `scripts/lib/` surface and a check script that proves them, including negative cases.
</objective>

  <action>
    Create `scripts/lib/portable-text-walk.ts`. Use the `node:` prefixed import form for any builtin, which is the Phase 2 convention. This module has no imports from `src/` and no side effects on import.

    Define local types for the shapes RESEARCH measured: a span is exactly `{ _key, _type: "span", marks: string[], text: string }`; a block carries exactly `_key, _type, children, level, listItem, markDefs, style`; an image block carries `_key, _type, alignment, alt, asset, width` and may additionally carry `crop`/`hotspot` in the dev dataset; a table is `{ _key, _type: "table", rows: [{ _key, _type: "tableRow", cells: string[] }] }`. Type the block container permissively (`[k: string]: unknown`) so undeclared fields survive.

    Implement ONE private enumerator, for example `walkSlots(body, visit)`, that both public functions call. This is the central design constraint: extraction and reapplication must never be able to disagree about which slots are translatable, and the only way to guarantee that is a single traversal used by both. The enumerator visits, in strict document order:
    1. `_type === "block"`: each entry of `children` in array order where `_type === "span"` and `text` is a non-empty string, kind `span`
    2. `_type === "image"`: `alt` when it is a non-empty string, kind `alt`
    3. `_type === "video"`: `caption` when it is a non-empty string, kind `caption`
    4. `_type === "table"`: each entry of `rows[].cells` in row order then cell order where the entry is a non-empty string, kind `cell`
    5. any other `_type`: contribute nothing and recurse into nothing
    Rule 5 is the D-13 boundary and the success-criterion guarantee at the same time. The corpus contains zero code blocks today, so "code blocks pass through untouched" is a property of rule 5 rather than something to hunt for in data. Add a comment saying exactly that, so a future reader does not mistake the absence of a code branch for an oversight.

    Export `extractTranslatables(body): Translatable[]` where `Translatable` is `{ text: string; kind: "span" | "alt" | "caption" | "cell"; label: string }`. The `label` is a stable human location string built during the walk, for example `block[7]/span[2]`, `table[12]/row[1]/cell[3]`, `image[4]/alt`. The verify pass and `translationNotes` use these labels for location context, so they must be deterministic and derived only from array positions.

    Export `toTexts(items): string[]`.

    Export `applyTranslatables(body, texts: string[]): Body`. Deep clone with `structuredClone` and assign only into the enumerated slots, consuming `texts` in enumeration order. Throw an Error naming both counts when the consumed count and `texts.length` differ, in either direction. Assign nothing else. Reuse every source `_key` verbatim: this module performs no id generation of any kind, because a fresh key is a structural mutation that the fingerprint gate would correctly refuse.

    Export `structuralFingerprint(body): string`, implemented as `JSON.stringify(applyTranslatables(body, new Array(extractTranslatables(body).length).fill("\u0000")))`. Deriving the fingerprint from the walker rather than from an independent replacer is deliberate: it guarantees the gate blanks exactly the slots the walker owns and compares every other leaf verbatim, and it stays correct when the content model grows. Add a comment stating that this is a tripwire on the walker and the reassembly path, not on the model, and that it should be impossible to fail, which is the point.

    Carry a header docblock naming the trap being avoided (whole-document JSON translation renumbering keys and mangling hrefs) in the Phase 2 comment-the-why style.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model response to content store | Translated strings originate outside the system and are reassembled into documents that will be published |
| unknown future block type to walker | Content model growth crosses into code that decides what may be mutated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Tampering | Portable Text reassembly | high | mitigate | `applyTranslatables` deep clones and assigns only into enumerated slots; `structuralFingerprint` is derived from the same enumerator so every unowned leaf is compared verbatim; six negative fixtures prove the comparison actually detects mutation |
| T-03-19 | Tampering | `markDefs` link hrefs | high | mitigate | Link annotations are never enumerated as translatable, so they are never sent to a model, and section D asserts that changing an href changes the fingerprint |
| T-03-20 | Tampering | undeclared or future block types | medium | mitigate | Rule 5 contributes nothing for an unknown `_type`, and section E proves a synthetic code block survives a full substitution round trip byte identical |
| T-03-13 | Repudiation | ambiguous empty `translationNotes` | low | mitigate | `formatNotes` emits an explicit clean line, so a blank field means the pipeline never ran rather than the pass being clean (D-06) |
| T-03-17 | Information Disclosure | live check output | low | accept | The live section prints counts and one slug; slugs are public URLs and no token, env value or body text is printed |
</threat_model>
