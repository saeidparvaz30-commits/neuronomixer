Output: a script that can be run today, prints exactly what it would do, and writes nothing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env file to script target | The choice of `--env-file` decides whether reads and writes land on the dev or the production dataset |
| CLI argument to GROQ | A `--slug` value from the command line reaches the query engine |
| script to run-state artifact | Run state is written into a version-controlled planning directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | dataset selection | high | mitigate | No `??` fallback on the dataset, header line printed before the first read, production banner on a mutating production run, and dry run as the default so a forgotten flag writes nothing (D-14) |
| T-03-07 | Denial of Service | runaway multi-post paid run | medium | mitigate | Dry run default, an estimated cost printed before submission, `--slug` for the single-post gate, and `--all` required before `--execute` will process more than one post |
| T-03-09 | Tampering | GROQ injection through `--slug` | high | mitigate | The slug is passed as the `$slug` parameter; an acceptance criterion asserts the script contains no hand-built GROQ filter text |
| T-03-12 | Tampering | clobbering a hand-edited Farsi draft | medium | mitigate | Stale siblings are reported only; the working set excludes them unless `--retranslate` is passed, and retranslations are labelled with their existing sibling id in the printed plan |
| T-03-08 | Tampering | `TokenUsage` foreign key | medium | mitigate | `resolveAdminUserId` runs before anything is submitted and is fatal in `--execute` mode |
| T-03-04 | Information Disclosure | run-state artifact and console output | high | mitigate | The artifact carries ids, labels, counts and fingerprints only; an acceptance criterion asserts it contains no key prefix and no Postgres URL scheme; the header prints only `projectId`, `dataset`, `apiVersion` and mode |
| T-03-28 | Spoofing | write-scope failure discovered after a paid run | medium | mitigate | One server-validated `commit({ dryRun: true })` proves the token carries write scope on this dataset before any batch is created |
</threat_model>
