  <name>Task 1: Implement the --post-run mode of translation.check.ts</name>
  <files>scripts/checks/translation.check.ts</files>
  <read_first>
    - `scripts/checks/translation.check.ts` as it stands after plans 03-03 and 03-05, including the reserved `--post-run` stub and the live client construction
    - `scripts/checks/language-filter.check.ts` lines 487-560 and 645-680: the live section shape, the separately constructed raw-perspective client with its comment, and the summary convention
    - `.planning/phases/03-translation-pipeline/03-RESEARCH.md` "Phase Requirements to Test Map": every `--post-run` row it names
    - `scripts/lib/portable-text-walk.ts` and `scripts/lib/translation-notes.ts`
    - `.planning/phases/03-translation-pipeline/artifacts/preflight.md`: whether this env file can reach the `TokenUsage` table
  </read_first>
  <action>
    Replace the reserved `--post-run` stub with a real implementation. It takes `--slug <value>` to name the post to inspect, and falls back to inspecting every Farsi document in the dataset when no slug is given. It is read-only.

    Build one client with `perspective: "raw"` and a comment saying why, following the one-client-per-perspective rule the sibling check already uses.

    For the named post, fetch the English source and its Farsi sibling and assert, each with a message stating expected versus actual and the remedy:
    - the sibling `_id` begins with `drafts.`, so it is a draft and not a published document
    - `language` is fa and `translationOf._ref` equals the English source `_id`
    - `status` is the draft value
    - `slug.current` on the sibling equals the source's, since the design reuses the English slug verbatim
    - `sourceUpdatedAt` equals the source `_updatedAt`
    - `structuralFingerprint(sibling.body)` equals `structuralFingerprint(source.body)`
    - every `markDefs[].href` across the sibling body, in document order, equals the source's list exactly. This duplicates part of what the fingerprint already covers, deliberately: links working is a named roadmap success criterion and deserves its own named assertion and its own failure message
    - the sibling has no `featured` key and no `heroOrder` key
    - `translationNotes` is a non-empty string that either equals the clean-line form or begins with the findings header form, and contains no em dash
    - anti-vacuity: at least 80 percent of the sibling's translatable strings differ from the source's, and at least 80 percent of them contain at least one character in the Arabic script Unicode range. Without this, a walker that silently copied the English through would pass every structural assertion. This is the same discipline as the parity guard in `language-filter.check.ts`

    Dataset-wide assertions, run regardless of slug:
    - `count(*[_type == "post" && language == "fa" && status == "scheduled"])` is 0. This is the D-12 tripwire at the data layer and it must stay in the check permanently, not just for this run
    - every Farsi document in the dataset has a `translationOf` reference that resolves to an existing post
    - no two Farsi documents share a `translationOf` target

    Spend assertion, gated on `DATABASE_URL` being defined: query `TokenUsage` for rows whose `activity` is `translate-post` or `translate-verify` created within the last 24 hours, and assert both activities are present with a non-zero `totalTokens` and, where the row records a cost, a cost of 0, because the run is subscription-funded (D-16). When `DATABASE_URL` is absent or the preflight artifact recorded that this database cannot be reached, print a clearly labelled SKIPPED row naming the reason rather than passing silently.

    Keep the counted summary line and the terminating ALL PASS convention. Print the sibling `_id`, the item count, the percentage of strings that changed and the percentage carrying Arabic script, so the run log carries real numbers.
  </action>

| T-03-03 | Elevation of Privilege | a Farsi document reaching the publish-scheduled cron | critical | mitigate | The `--post-run` mode asserts a dataset-wide count of zero Farsi documents carrying the status the cron matches on, and that assertion stays in the check permanently rather than only for this run |
