<objective>
Produce the first-pass Farsi glossary and the review surface Saeid corrects it on, plus the loader that injects it into the translate prompt as a cache-stable system block.

Purpose: a single glossary, prompt-cached and correctable in one place, is what keeps Farsi ML and finance terminology from drifting post to post. D-03 promises Saeid a review table with real corpus frequency and a real example sentence per term, which means the counts have to be computed in code; a model-estimated frequency would be a fabrication presented as evidence.
Output: `content/fa-glossary.json`, `content/fa-glossary-review.html`, a validated loader, and offline assertions covering all of it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| production Content Lake to script | The full published corpus is read into a local process and partially into a model request |
| model response to repository | Model-selected terms and renderings become a version-controlled file that shapes every future translation |
| glossary file to prompt cache | The serialized block is a stable prefix shared by every request in a run |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-24 | Tampering | fabricated corpus frequencies | medium | mitigate | Frequencies and example sentences are counted and extracted in code; a model-returned term that is absent from the candidate artifact is dropped rather than given an invented count |
| T-03-25 | Tampering | cache prefix instability | medium | mitigate | `serializeGlossaryBlock` sorts by term and omits frequency, example and any date; the check asserts byte identity across two independent loads and asserts no year pattern appears in the block |
| T-03-26 | Tampering | malformed glossary reaching a paid batch | medium | mitigate | `loadGlossary` validates version, entry count, required fields and the strategy union, throwing before any request is built |
| T-03-05 | Tampering | prompt injection via post text in the mining corpus | medium | mitigate | The classification response is schema constrained to term, rendering and strategy triples with an enum on strategy, and every returned term is joined back against the locally computed candidate list before it can enter the file |
| T-03-07 | Denial of Service | token overspend on the mining call | low | mitigate | One request over a few hundred candidates rather than the 84k-token full corpus; `--check` reports without spending; spend is recorded through `TokenUsage` |
| T-03-04 | Information Disclosure | script output and the review HTML | medium | mitigate | The header prints `projectId`, `dataset`, `apiVersion` and mode only; the review HTML contains published post text and slugs, which are already public |
| T-03-01 | Tampering | wrong dataset | high | mitigate | No `??` fallback on the dataset, header line before the first read, and this script performs reads only against Sanity |
</threat_model>
