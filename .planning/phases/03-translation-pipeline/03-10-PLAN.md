| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03-03 | Elevation of Privilege | Farsi document versus the publish-scheduled cron | critical | mitigate | The document is created under a `drafts.` id with the draft status; the cron's client uses the default published perspective and cannot see drafts; the post-run check asserts a dataset-wide count of zero Farsi documents carrying the status the cron matches on, on production specifically |
| T-03-23 | Tampering | Phase 2 ordering invariant | critical | mitigate | Task 2 refuses to run until `deploy-gate.md` shows a Post-deploy section, so the English filter is provably live before the first production Farsi document exists; Step 4 re-proves the English site is unchanged afterwards |
| T-03-01 | Tampering | production write scope | high | mitigate | The run is a single `--slug` post authorised by name at a blocking human gate; `--all` with `--execute` is explicitly forbidden in this plan; the captured header and production banner are asserted verbatim |
| T-03-02 | Tampering | structural damage to a real published post's translation | high | mitigate | The code-side gate ran before the write and the post-run check re-proves fingerprint parity and ordered href parity against the live document |
| T-03-31 | Repudiation | machine-generated content under Saeid's byline without review | high | mitigate | The output is a draft, never a published document. Task 3 puts Saeid's own reading of the Farsi in the loop as a blocking gate, which is the reason the whole pipeline writes drafts |
| T-03-04 | Information Disclosure | the production run log | high | mitigate | An acceptance criterion asserts the log contains no key prefix and no Postgres URL scheme |
| T-03-07 | Denial of Service | token overspend on production content | medium | mitigate | One post, named by Saeid, with the cost printed by the dry run before submission; the backlog sweep is deferred to Phase 5 |
